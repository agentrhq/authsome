Zapier uses a long-lived API key. Authsome stores the key encrypted in the local vault, injects it at request time through the proxy, and keeps it out of shell history, process listings, and environment dumps.

## At a glance

| | |
|---|---|
| Provider name | `zapier` |
| Display name | Zapier |
| Auth type | API key |
| Header | `Authorization: Bearer <key>` |
| Proxy host | `api.zapier.com` |
| Env var | `ZAPIER_API_KEY` |
| Where to get a key | [https://developer.zapier.com/api-keys](https://developer.zapier.com/api-keys) |

## Get a key

Create an API key in the Zapier dashboard at [https://developer.zapier.com/api-keys](https://developer.zapier.com/api-keys).

## Log in

```bash
authsome login zapier
```

A local browser form opens at `http://127.0.0.1:7998`. Paste the key into the masked input and submit.

<MaskedInputNote />

Verify:

```bash
authsome get zapier --field status
# → connected
```

## Use the key

Run the agent under the proxy (recommended). 

<CodeGroup>

```bash Proxy (recommended)
authsome run -- python my_agent.py
```

```bash Environment
eval "$(authsome export zapier --format env)"
echo $ZAPIER_API_KEY
```

</CodeGroup>

Under the proxy, authsome sets `ZAPIER_API_KEY=authsome-proxy-managed` in the child's environment and injects the real key into outbound requests to `api.zapier.com`. The child process never sees the actual value.

## Multiple keys

<MultiConnectionsCta />

```bash
authsome login zapier --connection personal
authsome login zapier --connection team
```

## Rotate or remove the key

```bash
authsome login zapier --force          # rotate
authsome logout zapier                  # remove local credential
authsome remove zapier                  # remove all local state for the provider
```

API-key providers have no revocation endpoint, so `revoke` and `remove` are equivalent for Zapier.

## Override the bundled definition

```bash
authsome inspect zapier > ~/.authsome/providers/zapier.json
# edit fields
authsome list   # source now shows "custom" for zapier
```
