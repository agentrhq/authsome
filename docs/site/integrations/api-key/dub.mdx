Dub.co uses a long-lived API key. Authsome stores the key encrypted in the local vault, injects it at request time through the proxy, and keeps it out of shell history, process listings, and environment dumps.

## At a glance

| | |
|---|---|
| Provider name | `dub` |
| Display name | Dub.co |
| Auth type | API key |
| Header | `Authorization: Bearer <key>` |
| Proxy host | `api.dub.co` |
| Env var | `DUB_API_KEY` |
| Where to get a key | [https://app.dub.co/settings/tokens](https://app.dub.co/settings/tokens) |

## Get a key

Create an API key in the Dub.co dashboard at [https://app.dub.co/settings/tokens](https://app.dub.co/settings/tokens).

## Log in

```bash
authsome login dub
```

A local browser form opens at `http://127.0.0.1:7998`. Paste the key into the masked input and submit.

<MaskedInputNote />

Verify:

```bash
authsome get dub --field status
# → connected
```

## Use the key

Run the agent under the proxy (recommended). 

<CodeGroup>

```bash Proxy (recommended)
authsome run -- python my_agent.py
```

```bash Environment
eval "$(authsome export dub --format env)"
echo $DUB_API_KEY
```

</CodeGroup>

Under the proxy, authsome sets `DUB_API_KEY=authsome-proxy-managed` in the child's environment and injects the real key into outbound requests to `api.dub.co`. The child process never sees the actual value.

## Multiple keys

<MultiConnectionsCta />

```bash
authsome login dub --connection personal
authsome login dub --connection team
```

## Rotate or remove the key

```bash
authsome login dub --force          # rotate
authsome logout dub                  # remove local credential
authsome remove dub                  # remove all local state for the provider
```

API-key providers have no revocation endpoint, so `revoke` and `remove` are equivalent for Dub.co.

## Override the bundled definition

```bash
authsome inspect dub > ~/.authsome/providers/dub.json
# edit fields
authsome list   # source now shows "custom" for dub
```
